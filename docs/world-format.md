# 持续战役配置：准备局面，让玩家创造故事

持续战役放在 `content/worlds/<id>.json`。它准备地点、人物、可取得的进展和不介入时的变化，不规定玩家必须按哪条剧情走。一级角色可以大胆创作身世，但“自称王子”“三个人穿一件斗篷”首先是人物声明；属性、动作和资源以角色卡为准。

[world.schema.json](../content/world.schema.json) 是字段与取值的唯一格式合同；[world-validation.mjs](../lib/game/world-validation.mjs) 检查引用、连通性和前提关系。[月桥镇范例](../content/worlds/moonbridge-conspiracy.json) 可以直接交给 AI 参考。本文说明如何写出好玩的局面，不另定义字段。线性教学短篇仍使用 [schemaVersion 1](campaign-format.md)，两种格式不能混写。

## 文件与版本

配置采用 UTF-8 JSON、两空格缩进和末尾换行。固定 `$schema: "../world.schema.json"`、`format: "situation-v1"`、`schemaVersion: 2`、`rulesVersion: "srd-5.1-table-2"`。`id` 是稳定英文标识；修改已有内容时递增 `revision`，不要把修订号当作软件版本。

`order` 决定大厅顺序；标题、简介、主题、难度和 `minutes` 是展示文案。时长应写成估计，不能用“每晚四小时、一定玩十次”承诺玩家体验。`hook` 是开场可见信息，不能包含谜底。地点数组第一项是出生点。

新存档保存整份配置快照及修订号。后来增加或修订剧本，旧存档仍使用出发时的内容。新增规则版本需要引擎支持或明确迁移，不能只把字符串换成新的版本号。

## 六种内容各自负责什么

| 内容 | 作者准备什么 | 运行时如何使用 |
| --- | --- | --- |
| `locations` | 地点描述、出入口、在场人物、安全休息条件 | 玩家可以沿 `exits` 移动和回访；未相邻地点不能瞬移 |
| `npcs` | 名字、公开角色、想要什么、秘密、所在地点 | 当前人物的角色、欲望和有限信任展示给玩家；`secret` 不直接发给玩家或叙事模型 |
| `clues` | 有标题与内容的真实发现 | 只有引擎实际发放后，才进入玩家和 AI 的已知事实 |
| `objectives` | 可持续记录的世界改变 | 成功机会或时钟阈值使目标成立；仅已完成的改变公开展示，未知描述不提前发给玩家或 AI；不能由一段 AI 对话直接写入 |
| `opportunities` | 当前局面中可能取得的进展 | 按地点与已知线索开放；玩家既可用建议方法，也可描述适合目标的新方法 |
| `clocks` | 无人介入时怎样变化，以及什么行动能稳定局势 | 行动、失败和休息推进刻度；阈值可发放明确线索或目标，不能自行结束战役 |

所有 ID 引用必须存在，各个带 `id` 的数组内部不能重名，包括 `backstoryHooks`；不使用表达式、脚本、外部 URL 指令或动态代码。NPC 的 `location` 和该地点 `npcIds` 必须一致，同一个 NPC 只能列在其声明地点。出入口是有方向的；希望双向通行就两边都写，不能假设引擎自动补路。

## 一个机会的规则

机会的 `prompt` 写玩家看得到的问题与一个建议方法，不写成功后的秘密。`requires` 是需要已经获得的**线索 ID**，不是目标或任意条件表达式。`skills` 声明该目标支持哪些适合的方法；当前 DC 允许 10、12、15、18。想容许更多创意，声明合理的多项技能，并让描述解释它们怎样接近目标。

`success` 明确写 `text`、`clues`、`objectives`；没有奖励时用空数组。可选 `trustNpc` 只提升当前在场人物的一格态度，可选 `ending` 指向一个结局。`failure.text` 必须与失败时真实成立的状态一致；`failure.clock` 是额外耗时 0–2 格。不能写“失败也拿到了同一张秘密账本”而不配置发放，更不能把人物死亡或物品损坏只写进文案。

机会的结果已经全部成立时，等效机会会关闭，避免先成功救人又被描述成救援失败。显式结局选择保留到玩家实际选择为止。失败的相同方法不能原地重掷；改用另一办法或取得相关准备后，可以重新提出裁定。准备带来的优势只消费一次。

可选 `encounter` 声明一个对手，使用 schema 中支持的生命、护甲、攻击与伤害字段，可选 `sleepImmune` 明确睡眠免疫。战斗属于可选办法；给同一问题留下交涉、调查或绕行路径。当前采用单一对手与抽象站位，不能配置网格距离、群体目标或未实现的特殊攻击。胜利取得该机会的配置结果，并留在当前地点。

## 时钟与结局

时钟刻度是**叙事进度**，法术持续时间另按实际分钟保存。通常赶路或一次探索行动推进 1 格，失败再增加配置的额外格数；独立施法推进 1 格，仪式额外 1 格，短休 6 格，章节休整 8 格。关闭程序不会推动刻度。

每个阈值有 `at` 和公开事件 `text`，可选一个 `clue`、一个 `objective`。阈值须在 `max` 内且不重复。`stoppedBy` 是目标 ID 数组，其中任意一个已完成便停止该时钟。让事件带来新线索、第三方介入或新的代价，可以防止关键骰子失败后故事停住；阈值文案必须对应实际配置效果。

结局必须包含引擎保留的 `retreat`。其他结局通过某个机会的 `success.ending` **明确选择**，并可声明 `requires` 目标与 `clues` 线索。这些条件必须在选择结局前由普通机会或时钟取得，不能依赖任何结局选择完成后才发放的结果；战役结束后不能继续行动来解锁另一个结局。抵达最后一个地点、时钟走满或 AI 说“故事结束”都不会自动触发结局。条件未成立的选择不会出现。

## 人物背景如何接进故事

`backstoryHooks` 准备当前位置可问玩家的话题，包含位置、问题、标签和固定 `truthStatus: "unresolved"`。它是 DM 的谈话入口，不能凭标签向玩家发放血统能力、王位、魔法物品或世界秘密。当前标签是作者整理信息，不自动匹配人物经历或改写剧情。

DM 会读取角色的性格、理想、羁绊、缺点、目标、合作理由和过去，再用这些信息扮演回应。持久事实是已知线索、目标、人物信任、时钟和已执行行动；未证实身份记录为人物声明。事件手记保留最近 300 项，聊天保留最近 180 条；长期结果保存在独立状态，不依赖把整段历史塞给模型。

自由行动每次只裁定一个目的：取得当前机会、前往相邻地点、和在场人物交涉，或完成有限准备。AI 可以理解方法与提出裁定，但不能发放任意新能力、装备、金钱、伤害或隐藏真相。没有对应机会的准备成功，会为当前位置下一次同技能目标检定提供一次优势；交涉只能有限改变态度，说服不是精神控制。真实可用的探索法术才可参与行动，确认后才消耗资源。

## 生成、检查、试玩

把 [持续战役生成提示词](world-generation-prompt.txt)、schema 与范例同时交给 AI；只接收配置文件，不让模型改写引擎。生成后先单文件校验，再加入仓库：

```sh
node scripts/content-workflow.mjs --file content/worlds/my-adventure.json
npm run content:sync
npm run content:check
npm test
npx tsc --noEmit
```

依赖检查会计入机会与时钟阈值可能提供的线索和目标，并排除结局用自身结果解锁自己的循环；它不模拟所有移动顺序、提前停钟与其他动态分支。格式检查不会证明故事有趣，也不能证明每个动态路径都畅通。至少试玩一条成功路线、一条连续失败路线、一次主动回访、一次违背 NPC 意愿的请求，以及每个结局的真实行动流程。检查的重点是：奖励是否实际发放、文案是否与状态一致、失败后是否还有有意义的选择、休息时世界是否仍会变化。
