# 剧本配置与扩展

一份剧本是一份 UTF-8 JSON。它描述故事、场景、可执行行动和结局，规则引擎负责结算，AI 负责理解输入与叙事。新增符合现有能力的冒险，只需增加 JSON 文件，再运行校验和构建；不用为每个剧本写业务代码。

唯一格式定义是 [JSON Schema](../content/campaign.schema.json)，跨字段与可达性检查在 [content-validation.mjs](../lib/game/content-validation.mjs)。已有的 [失声的钟楼](../content/campaigns/silent-bell.json) 是完整范例；本说明解释这些约束，不另设一套字段定义。

## 文件与版本

文件放在 `content/campaigns/<id>.json`，两空格缩进、末尾换行。ID 使用小写英文、数字与连字符，以英文字符开头，最多 48 字符。场景 ID 和行动 ID 在整个剧本中分别唯一；线索和标记不能同名。不要给配置添加 JavaScript、表达式、模板执行器或自定义命令。

| 字段 | 含义 |
| --- | --- |
| `$schema` | 固定为 `../campaign.schema.json`，供编辑器关联格式 |
| `schemaVersion` | 当前为 `1`，描述配置结构 |
| `rulesVersion` | 固定为 `srd-5.1-teaching-1`，描述结算规则与房规 |
| `revision` | 正整数；修改内容时递增 |
| `order` | 大厅排序，数值小的在前 |
| `id`、`title`、`subtitle` | 稳定身份与展示标题 |
| `description`、`hook` | 大厅介绍与开场；避免直接透露谜底 |
| `minutes`、`theme`、`difficulty` | 展示用文案，时长是估计，不是倒计时 |
| `flags` | 声明所有故事标记；标记自身不会改变数值 |
| `clues` | ID 到 `{title, text}` 的字典；仅在实际获得后展示 |
| `scenes` | 2–10 幕，数组索引从 `0` 开始 |
| `endings` | 结局字典，必须有引擎保留结局 `retreat` |

创建冒险时，服务端把完整配置、修订号和规则版本写入该存档。以后更新或移除大厅里的剧本，旧冒险仍使用自己的配置快照。快照和未来场景不会发给浏览器或叙事模型。升级规则引擎时，需要显式保留旧 `rulesVersion` 的实现或编写迁移，不能只改版本字符串。

## 场景与行动

每幕包含 `id`、`title`、`description`、`npc`、`actions`。`npc` 是 AI 可使用的当前公开人物信息，不是秘密答案区。`safeRest: true` 表示该场景允许全队短休；放在合理安全且有机会受伤后的地点。需要战斗时，同一幕同时声明 `enemy` 与一个战斗行动。

| `kind` | 需要的字段 | 引擎行为 |
| --- | --- | --- |
| `automatic` | 常规行动字段与至少一个效果 | 点击确认即执行，不掷骰；可有 `timeCost` |
| `check` | `skill`、`dc`、`consequence` | 先锁定难度和失败代价，玩家确认后掷骰；失败不能原地重试 |
| `combat` | `next`，以及本幕 `enemy` | 自动掷先攻；胜利执行 `next` 和可选 `clue` |

所有行动都需要 `id`、`title`、`description`。支持的效果和前提：

| 字段 | 精确含义 |
| --- | --- |
| `next` | 成功后跳转到**更大的、存在的**场景数组索引；不支持回跳或循环 |
| `ending` | 成功后结束冒险，引用已声明的故事结局；不能同时写 `next` |
| `clue`、`flag` | 成功后发放线索或标记；引用必须已声明 |
| `requiresClue` | 拥有该线索才显示此行动；不是“掷骰更难” |
| `advantageFlag` | 检定时若有该线索或标记，掷两颗 d20 取高值；只用于 `check` |
| `failureDamage` | 检定失败额外扣 1–3 生命；写出的失败文案必须与数值一致 |
| `timeCost` | 自动行动增加 1–2 危险，必须在行动文案说明；不是真实时钟 |

技能固定为 `athletics`（运动）、`stealth`（隐匿）、`investigation`（调查）、`perception`（察觉）、`insight`（洞悉）、`persuasion`（说服）、`arcana`（奥秘）。选与行为相符的技能，不以隐匿代替平衡或说服。难度范围 5–20，教学模组通常 10–13。

所有检定失败自动增加 1 危险，停留原场景，发放的线索/标记/成功跳转均不执行。`consequence` 只解释已实现的后果：时间流逝、危险增加、以及配置了的伤害。禁止写“失去金币”“获得伤势”“永久减属性”等尚未实现的机制。无伤害字段就不能宣称扣血。若想要新机制，先扩展引擎、Schema 与验证，再生成使用它的剧本。

敌人只支持 Schema 中列出的数值：初始 `hp === maxHp`，护甲、攻击加值、d4/d6 伤害、固定伤害加值与敏捷调整值。多人战斗每增加一位队员，敌人生命上限增加 4；AI 不得自创抗性、状态、多次攻击或新法术。

## 防止故事卡死

每幕必须有一个**不需要线索、不消耗资源、不要求战斗**的自动推进或自动结局，可以用等待、绕路、求援等时间代价换取。这条路是连续失败后的保底路径。必需线索不要只放在可能失败的检定里；可选线索可以影响优势或替代结局。

校验器从零线索、零标记开始探索合法状态，拒绝线索依赖闭环、无法执行的奖励、不可达场景/结局、未知引用、重复 ID、倒退跳转、未使用的结局与无人发放的线索。结束分支不会把线索传给别的分支。超过 20,000 个抽象状态会要求简化分支，而不是跳过验证。

`retreat` 是玩家撤退或生命归零救援时的结局。教学模式中任意队员生命到 0 会结束整队冒险，因此撤退结局应同时适用于主动撤离与被救援，不要写角色死亡。危险上限为 6，达到 4 时，引擎给非撤退结局附加延误代价。结局文案应能容纳这段变化。

## 生成与接入

1. 把 Schema、[AI 生成提示词](campaign-generation-prompt.txt) 和一个完整范例交给 AI。先确定目标玩家、情绪、冲突和几种取舍，再生成 JSON。
2. 候选文件先放到剧本目录之外，运行 `npm run content:check -- --file <candidate.json>`。根据错误位置修正，不要通过放宽 Schema 来迁就错误输出。
3. 人工阅读：技能是否适合行为，失败文案是否对应实际效果，人物有没有动机，线索是否泄露，选择和结局是否有不同意义。校验通过不能证明故事好玩。
4. 移入 `content/campaigns/<id>.json`，运行 `npm run content:sync` 格式化并生成注册表，然后运行 `npm run content:check`、`npm test`、`npm run build`。
5. 在预览中至少走一次全失败路线、一次你最想展示的路线、一次战斗与撤退。通过后发布；新冒险会自动出现在大厅。

`lib/game/campaign-content.generated.mjs` 由脚本生成，不手改。校验器是命令行构建步骤；网站不接受用户上传配置或现场执行 AI 生成的代码。
