# 多人冒险：使用与协议

v0.3.0-beta.1 支持 2–4 人共用同一个世界，由房主保存角色、结算规则并连接 AI。参加者安装同一客户端，不需要账号、API Key 或 Codex 登录。本版已验证本机多进程传输与房间恢复；公网信令尚未部署，大陆跨运营商可用性待实测。

## 开一张桌

首页进入多人组队。房主先创建自己的角色，在 AI 设置中保存兼容 API，或安装官方 Codex 并完成浏览器登录；主动点击连接测试后，选择剧本、创建房间。每个参加者粘贴邀请后，使用完整角色表构筑自己的一级角色。服务端重新计算属性和装备，身世描述不授予规则之外的能力。

```text
同一个桌面窗口
├─ 单人大厅 → 创建角色 → 剧本 → 自动存档
└─ 多人组队
   ├─ 房主 → AI 设置 → 创建房间 → 发布入口 → 分享邀请
   └─ 参加者 → 粘贴邀请 → 角色表 → 同步席位 → 准备
                         全员准备 → 房主开始
```

开局前可以设置时限；开局后角色构筑、时限与新加入席位锁定。房主不能替队友授权资源消耗。离开多人栏目时，主持中的冒险先暂停，参加者先断开连接，再进入其他栏目。

## 两种连接方式

| 方式 | 房主需要准备 | 参加者操作 |
| --- | --- | --- |
| P2P 自动协商 | 部署包生成的公开连接配置，含 WSS 信令与 STUN 地址、证书及指纹 | 粘贴邀请，客户端验证房主后协商加密直连 |
| 高级 WSS 地址直连 | 可达的局域网地址、公网 IPv6，或已做 IPv4 端口映射的地址；放行房间端口 | 粘贴同格式邀请，客户端固定证书指纹并验证房主签名 |

域名不是必需条件。配置中的证书可以带 IP 地址；首次配置和邀请应经可信渠道取得。管理页面、AI 设置和本机数据库不暴露到网络。信令只交换协商信息，不转发游戏数据；无 TURN，连接失败不会悄悄转用中继。部署与端口详见 [signal/README_CN.md](../signal/README_CN.md)。

邀请外层最长 24 小时，每个新加入令牌只用一次。新朋友加入后，更新邀请再分享给下一位；旧席位恢复使用自己的独立恢复凭据。只在开局前加入新角色，最多包含房主在内四人。

## 怎样行动

探索时可以聊天、商量或申请行动。改变世界的操作排队进行，每位玩家完成一次主要行动后释放席位；取消裁定沿用本次行动剩余时间。战斗按先攻，不要求玩家自行决定轮到谁。

默认整次行动 90 秒，确认裁定最多 30 秒，团队决定最多 45 秒，AI 意图累计最多 45 秒。确认和投票共享父操作预算，切换阶段不会刷新整次时限。AI 理解期间暂停玩家钟，但排队与重复理解会消耗同一份 AI 额度。叙事在规则提交后后台补充，不占行动权；新的意图可取消旧叙事。实际默认与允许范围唯一来源为 [clock.ts](../local/rooms/clock.ts)。

旅行、短休、撤退和章节休整需要冻结席位的严格多数同意。离线或撤销访问不会降低已经开始的投票人数。短休获准后，每个人明确选择是否使用自己的生命骰或奥术回想；超时未授权的资源不消耗，世界时间只统一推进一次。

角色在多人冒险中降到 0 HP 会倒地，不能行动或维持专注，敌人忽略倒地角色。同地点队友可花自己的药水和主要动作救起，目标从后续自己的回合行动。全队倒地采用公开的新手救援房规；全员消极超时会在敌人结算前暂停，避免不断自动挨打。

## 断线、延迟和恢复

权威规则只在房主机运行。命令带唯一 ID、规则版本、操作与阶段 ID；原回执优先于当前阶段检查。同一 ID、同一内容返回原结果，同一 ID 换内容会拒绝。骰子、资源、回执、事件和阶段一起在 SQLite 提交。

客户端先将完整请求写入本机 SQLite 待确认日志，再发出行动；这份日志不依赖桌面窗口、浏览器内存会话或随机端口。丢响应时恢复同一请求，不补造新 ID；未连接时不能提交新行动。来宾额外保存加密席位凭据与加入恢复交换；首次加入、轮换凭据的响应丢失也不会多创建一个席位。

如果席位被移出或房主长期无法恢复，可以选择“结束恢复并离开此桌”。这会先暂停本机主持的冒险或离开来宾连接，再停止本机待确认重试；不会撤销房主已结算的行动，也不会删除原房间的存档与来宾恢复记录。

快照按服务重启代数、事件序号、规则版本和采集时间淘汰旧响应。重新建立传输后，先认证原席位、持久化凭据、同步快照和恢复待确认请求，再开放操作。连接由一个退避控制器重试，不同时启动多个恢复循环。

房主发出绑定本次连接的心跳挑战，客户端回显后才延长在线状态；普通推送不会替代往返确认。心跳间隔 10 秒，在线窗口 30 秒，传输扫描有一个周期的检测余量。全部非房主离线会暂停全桌，房主在线也不会无限自动代打。

房主重新启动会增加 epoch，并暂停存档、终止旧 AI 意图，不自动重发模型请求。**本版需房主手动重新发布网络入口**；原参加者继续已有席位，必要时粘贴同一房间的新邀请更新连接位置，再同步并由房主继续。没有自动恢复监听、运行中的房主迁移或重启后自动付费推理。

## 开发入口与验收

- `local/rooms/` 是同步权威状态机；不导入网络或 AI 实现。
- `local/room-gateway.ts` 是本机客户端网关，只向远端开放加入、恢复、公开快照与席位命令。
- `local/network/` 负责签名、证书固定、P2P、WSS、有界分片与连接重试。
- `local/client-journal.ts` 与 `app/table/request-journal.ts` 管理跨应用重启的待确认请求。
- `tests/rooms.test.mjs` 验证 SQLite、计时、投票、AI 围栏、完整两人故事路线与救援。
- `tests/room-gateway.test.mjs` 使用两个独立 SQLite 服务走真实本机 WSS，覆盖丢响应、重连鉴权和网络边界。
- `tests/network*.test.mjs` 使用原生传输与本机多进程验证连接、分片、断线和信令恢复。

本机测试不能替代公网验收。下一阶段在可用阿里云环境部署辅助服务后，使用至少两条真实外部网络验证 STUN 映射、非 relay 路径、双向消息、断网恢复、UDP 被封锁的失败提示和服务器重启。当前不承诺任何宽带组合均能直连。
