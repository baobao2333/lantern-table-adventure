# 用剧本工坊准备下一场冒险

从桌面侧栏打开「剧本工坊」。它保存的是主持人的完整配置，包含秘密与结局；作为玩家想保留悬念时，可以直接从大厅选择内置故事。

## 生成并开玩

先在「AI 设置」登录官方 Codex，或填写兼容 API 的地址、模型与密钥并测试连接。单人和房主共用本机 AI 设置。生成会使用所选账户的额度，最长等待两分钟；输出体积限制不是费用上限。

在工坊写下主题、人物冲突、想要的玩法和不想出现的内容，选择故事规模，再点击「生成剧本草稿」。小型局势目标是 4–6 地点，多晚冒险目标是 8–12 地点；实际讨论与探索时间取决于玩家。生成在本机后台执行，页面重新打开会恢复最近任务；未确认的提交会保留原请求 ID，点击恢复不会重复调用已接受的请求。取消只能停止本机等待和连接，服务商可能已消耗额度。

通过检查的草稿仍需阅读与试玩。确认后点击「保存到我的剧本」，再从下方选择「开始冒险」，创建角色或使用已有角色即可。生成不会自动开团，也不会把未经检查的内容放进剧本库。

## 从其他 AI 导入

点击「下载生成规范与范例」，把下载的 JSON 契约包完整提供给其他 AI。包内有唯一结构规范、运行语义说明、生成提示词和可用范例。要求它输出一份 `situation-v1` JSON，再导入工坊；单个格式化文件最大 512 KB。当前工坊不导入旧版线性短篇格式。

「校验草稿」检查结构、未知字段、ID 引用、地点连通、人物位置、线索依赖和结局前提。错误会显示字段路径或引用名称，修正后再次检查。配置只表达已实现的机制，不执行脚本；写出规则尚不支持的效果也不能让它生效。检查不穷举所有动态路线，至少试玩成功、连续失败、回访和各个结局。

## 修订与备份

新剧本使用新的稳定 ID，不能覆盖内置剧本。修改同 ID 剧本时增加 `revision`；完全相同的保存可安全重试，较旧版本不能覆盖较新版本。已有冒险保存独立快照，新修订只影响之后开的冒险。

「载入编辑」可取回保存的配置，「导出草稿」可下载完整 JSON。剧本库和最近 20 个生成任务保存在本机冒险 SQLite 数据库中，API 密钥仍由单独的加密设置保存。手工编辑但尚未保存的文本不会自动备份；离开前先保存或导出。程序重启会把未完成的生成标记为中断，需要重新生成，不会假称继续了模型请求。

## 开发验证

契约来源是 [world.schema.json](../content/world.schema.json)、[运行语义](world-format.md) 和 [生成提示词](world-generation-prompt.txt)。`content:sync` 把它们与范例生成到服务端专用模块，应用生成和下载使用同一份契约；不能直接编辑生成文件。

`npm test` 包含配置、版本、取消、重启与写入故障检查。`npm run verify:local` 使用隔离的 fixture API，通过实际打包 HTTP 服务完成生成、校验、保存、开团和重启验收，不使用真实模型。

需要真实模型验收时，先自行登录官方 Codex，再运行 `node scripts/verify-content-live.mjs`，可加 `--model <id>`。这项检查会真实调用账户，不在 CI 默认执行；验证生成配置通过规范、可保存及可初始化存档，并把配置和不含凭据的记录放在 `dist/acceptance`。它不证明每条动态剧情路线或故事质量。
